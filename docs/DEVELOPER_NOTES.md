# Технические заметки Albion Trade Desk

Локальная экономическая аналитика Albion Online. Основной сервер — **Asia / East**.
Светлый интерфейс с персиковыми и розовыми акцентами, русские названия, локальная
SQLite, без аккаунта и платных сервисов.

**Состояние: Phase 0 + прототип ядра Phase 1.** Реальный каталог загружен и
проверен; текущая облачная политика блокирует живой API AODP. Цены не выдуманы,
рабочая база не заполнена mock-данными. Полная проверка Asia и временных границ
history остаётся открытой. Производственные рекомендации и оптимизатор пока
не реализованы. Подробно: [дорожная карта](ROADMAP.md).

## Запуск на Windows

1. Установите **Python 3.12 или новее** с https://www.python.org/downloads/windows/.
   В установщике отметьте **Add Python to PATH**.
2. Скачайте/скопируйте папку проекта. Дважды нажмите **`start.cmd`**.
3. Откроется браузер с приложением. Окно консоли нужно оставить открытым.
4. В разделе «Данные и настройки» нажмите «Обновить список предметов».
5. Найдите предмет и нажмите «Узнать цену» в его строке. Для нескольких
   предметов отметьте галочки в первом столбце и нажмите «Загрузить цены выбранных».
   Один запрос обновления охватывает до 100 предметов, выбранный город и качество.
   Для сравнения городов повторите обновление в нужных рынках; карточка показывает
   только то, что действительно получено для каждого рынка.

Остановка: **Ctrl+C** в консоли. Данные и настройки сохраняются в папке `data`.
Если порт занят: `py -3 -m albion_trade_desk serve --port 8766 --open`.
Установка pip/npm-зависимостей для запуска **не нужна**. Windows здесь не
запускалась; совместимость кода проверяется также Windows-job в CI после push.

## Запуск в Linux / облачной среде

Из корня checkout `/workspace/MyLovelyAlbionAddon`:

```sh
python3 -m albion_trade_desk sync-catalog
python3 -m albion_trade_desk serve
```

Сервис слушает только `127.0.0.1:8765`. Можно открыть этот адрес в браузере **на
том же компьютере**. Это не опубликованный сайт. В облачном onboarding публичный
preview не настраивается. Исходники и установка сохраняются отдельно от живого
процесса: при новом запуске среды сервер надо запустить заново.

Другие команды:

```sh
python3 -m albion_trade_desk status
python3 -m albion_trade_desk probe --server east
python3 -m unittest discover -s tests -v
```

`--data-dir <путь>` меняет каталог базы. `probe` обращается к prices/history для
T4_BAG в Caerleon/BM и сохраняет **реальные** ответы с URL, временем и SHA-256
в `data/evidence/`. Ошибка даёт ненулевой exit code, не пустой успешный результат.

## Что есть в прототипе

* Импорт полного доступного каталога ao-bin-dumps: RU/EN, ID, категории,
  tier/enchantment, рецепты, выход за операцию, ингредиенты и невозвратные компоненты.
* Восемь рынков, отдельные Caerleon и BM, изоляция East/West/Europe и quality.
* Поиск RU/EN/ID, пагинация, фильтры по тиру, зачарованию, качеству, городу и
  категории, избранное, сохранённые профили. Базовая сортировка по названию/тиру.
* Источник/время наблюдения/получения, порог свежести, spread, эвристика выбросов.
* 1H/24H/7D по закрытым UTC-часам с покрытием, частичной суммой и «нет данных».
  VWAP, колебания цен интервалов и среднесуточный объём вычисляются на backend.
  Это не точное скользящее окно и не гарантия реализации партии.
* Обновления в фоне, batching, gzip, URL budget, SQLite-кэш, очередь,
  rate limit и ограниченный retry с exponential backoff/RateLimit-Reset.
* CSV/XLSX всего отфильтрованного набора, Power Query JSON API и SQLite backup.
* Экспериментальный локальный HTTP-ingress: формат проверен исходниками и
  тестами, но подключение реальной игры/клиента на Windows ещё не проверено.

В интерфейсе нет случайных «выгодных возможностей» при отсутствии цен. BM
показывает только buy order. Глубина неизвестна. Исторические средние не
подменяют текущие котировки. История 6h/24h хранится при импорте, но не
раскладывается искусственно по часам и не складывается с 1h.

## Excel

Кнопки CSV / Excel создают новый файл и **не меняют существующие книги**.
Лист `MarketPrices`, стабильные английские имена полей из `export.COLUMNS`.
Время — Unix seconds UTC; coverage — доля 0..1; null/пусто означает отсутствие
подтверждённой метрики. `known_*` — сумма доступных интервалов, не общий спрос.

Для Power Query: Excel → Данные → Получить данные → Из Интернета, укажите:

```text
http://127.0.0.1:8765/api/export.json?server=east&city=3005&quality=1
```

Раскройте `rows`, затем нужные столбцы. «Обновить всё» в Excel перечитывает
локальную базу; обновление самой базы из AODP запускается в приложении.
CSV: `/api/export.csv` с теми же параметрами. Импорт существующих Excel-книг,
остальные экономические наборы и контроль формул при импорте — следующие этапы.

## Private Market Scanner

Текущая интеграция описана в [PRIVATE_SCANNER.md](PRIVATE_SCANNER.md).
Используется отдельная opt-in сессия, единственный локальный ingest, пустой
personalized destination и отключённые WebSockets. Настройка с одновременной
публичной отправкой AODP не является приватным режимом и больше не предлагается
в пользовательском интерфейсе.

База мигрирует на v2 с резервной копией: ключи history/orders включают source.
Собственная история хранится отдельно от публичной. NATS — отдельный read-only
подписчик; в текущей облачной среде ему нужен поддерживаемый TCP-доступ.

## Разработка и доказательства

```sh
python3 -m unittest discover -s tests -v
node --check albion_trade_desk/static/app.js
```

Дополнительный UI smoke требует установленный Playwright и Chromium, запущенное
приложение с полным реальным каталогом. В этой среде они уже предоставлены:
`CHROMIUM_NO_SANDBOX=1 node tests/browser_smoke.cjs` (этот флаг нужен только для
Chromium в изолированном контейнере). В обычной системе используйте browser sandbox.
`CHROMIUM_PATH` и `ALBION_SMOKE_URL` позволяют задать пути. Browser smoke не
заполняет базу синтетическими рыночными ценами.

Аудиты: [конкуренты](COMPETITOR_AUDIT.md), [данные](DATA_SOURCE_AUDIT.md),
[архитектура](ARCHITECTURE.md), [формулы](ECONOMIC_MODEL.md),
[проверки и ограничения](VALIDATION.md).

Для этой среды сохранён черновик необходимых доменов. Чтобы разрешить живую
проверку AODP, сохраните сетевые изменения в настройках среды и опубликуйте её.
Это не требуется для обычного запуска на домашнем Windows с доступом в Интернет.


## Спокойный журнал и первый запуск

По умолчанию CLI печатает адрес фактически выбранного порта, подсказку о браузере
и важные этапы загрузки. Обычные HTTP GET/200 журналируются на уровне DEBUG;
включить их для диагностики можно флагом `--verbose`. Ошибки не подавляются:
фоновые задачи имеют status=error и сохраняют исходный текст для UI; интерфейс
показывает человеческое сообщение с раскрываемыми техническими деталями.

`/api/status.active_job` позволяет браузеру продолжить ожидание загрузки после
перезагрузки вкладки. Нулевой каталог блокирует сценарий выбора: главный экран
показывает одну заметную загрузку списка. Общие цены запрашиваются отдельно
кнопкой в строке, без необходимости выбирать checkbox.

## Наборы для крафта

`crafting.py` содержит выбор рецепта, количества, свежие котировки и базовый
бюджет. `static/crafting.js` — только интерфейс и копирование названий. Определения
наборов лежат в `craft_packs`, добавляемой без удаления прежних данных.
Формулы и ограничения — в ECONOMIC_MODEL.md. Ресурсные ID старых рецептов с
потерянным `@enchantmentlevel` разрешаются по каталогу при чтении.

Проверка браузерного сценария наборов:

1. Создать **новую временную** базу и загрузить настоящий каталог через
   `sync-catalog --data-dir <temporary-directory>` либо скопировать только
   таблицы `items` и `recipes` из каталожной базы.
2. Запустить `serve --port 8790 --data-dir <temporary-directory>`.
3. Выполнить `ALBION_CRAFT_TEST_DATA=1 ALBION_SMOKE_URL=http://127.0.0.1:8790 node tests/browser_crafting.cjs`.
   Нужны Playwright/Chromium, настройки пути и sandbox те же, что выше.

Этот тест **добавляет синтетические рыночные пакеты** через временный приватный
приёмник, проверяет прогресс в UI и изоляцию источников. Его запрещено запускать
на рабочей пользовательской базе. Сам Windows-launcher не исполняется, игра
не запускается. Скриншоты снимаются до добавления тестовых котировок.
`ALBION_ARTIFACT_DIR` задаёт каталог сохранения изображений; все проверки,
включая мобильную ширину, выполняются и без сохранения изображений.

## Качества, история и пользовательская книга

`analytics.qualities` поддерживает exact/auto/all; `by_quality` всегда сохраняет
раздельные значения. `history_view` строит график точного качества и валидирует
период до 90 дней. `/api/history/refresh` читает AODP с date/end_date/time-scale=1.
Сеть по-прежнему может отклонить запрос; ошибка не заменяется пустым успехом.

`refining.py`, `/api/cloth`, `/api/cloth/calculate`, `/api/cloth/save` и
`/api/cloth/export.xlsx` используют один конечный расчёт возврата. Схема
`user_settings` добавляется без удаления прежних данных. Пакет включает
`templates/*.json` и `templates/*.xlsx`, runtime остаётся stdlib.

`python3 scripts/validate_cloth_workbook.py` требует openpyxl/LibreOffice только
для разработки. `--cache-template` сначала пересчитывает и обновляет кэш шаблона,
сохраняя его формулы. Генератор `scripts/build_cloth_template.py <original.xlsx>`
нужен только для пересборки структуры, после него запускается cache/validation.
Нельзя запускать браузерный `browser_quality_cloth.cjs` с рабочей базой:
это тест отдельной базы с заранее заданными синтетическими ценами/историей.
