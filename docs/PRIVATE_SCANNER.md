# Private Market Scanner

**Статус: эксперимент, выключен по умолчанию. Критерий полной готовности ещё
не выполнен:** отсутствует проверка настоящего Windows-клиента при ручном
просмотре рынка, проверка Windows Firewall в такой сессии и подтверждение
соответствия актуальным правилам Sandbox Interactive. Пакет в SQLite или
зелёный статус приёмника не доказывают отсутствие других отправок.

Простые шаги установки находятся в [README](../README.md). Ниже — точная
граница гарантий, настройки и проверяемые свидетельства.

## Как работает режим

Пользователь вручную просматривает рынок. Официальный Data Client отправляет
рыночные JSON в единственный локальный HTTP-приёмник Trade Desk. Приложение
сохраняет записи в SQLite с `source=private-client` и **не имеет uplink из
этого приёмника**. Нет облачной синхронизации, пересылки в AODP, собственного
перехватчика пакетов, автоматизации UI игры или обхода шифрования.

Предпочтительный адрес приложения — `127.0.0.1:8765`. Если его занимает
AnkiConnect или другой процесс, приложение эксклюзивно занимает следующий
свободный порт и открывает правильный адрес. Windows `SO_REUSEADDR` больше
не используется: он мог позволять совместное занятие порта. Адрес для клиента
генерируется из **фактически занятого порта**, не прописывается в ярлыке вручную.

Каждая вручную включённая сессия получает временный адрес с непредсказуемым
токеном. Токен не попадает в обычные журналы HTTP или SQLite. Остановка сессии
аннулирует адрес; перезапуск программы не включает сканер снова. Регион
фиксирован в сессии. Несовпадающий регион/старый адрес/личная тема отклоняются.

Включение разрешено только после явного подтверждения экспериментального
статуса в UI. Это не юридическое подтверждение разрешения SBI.

## Проверенные настройки официального клиента

Изучены `client/config.go`, `dispatcher.go`, `uploader_http.go`,
`uploader_nats.go`, `lib/market.go`, `lib/marketHistory.go` и код updater.
Ревизия: `c6edd9456bec4657755c25f173e8ebc7a31a17f7`.

| Параметр/канал | Поведение | Приватный запуск |
|---|---|---|
| `-i` | Public-format сообщения направляются всем адресам через запятую | **Только один локальный HTTP destination** текущей сессии; без magic AODP URL |
| `-d` | DisableUpload останавливает любой uploader, включая локальный HTTP | **Не используется**; wire-тест подтверждает блокировку локальной отправки |
| `-p` | В этот канал поступают также персонализированные сообщения; туда же dispatcher дублирует публичные | Явно **пустой** `-p=`. Не настраивается даже на локальный приёмник |
| WebSocket | Отдельная отправка и public, и personalized сообщений, не полностью контролируется `-d` | `EnableWebsockets=false`, изолированная рабочая папка/config.json |
| NATS uploader | Publish сообщений, а не подписка на публичные данные | В клиенте приватного режима не настраивается |
| Updater | Отдельные внешние проверки обновлений в полном клиенте | Внешний трафик выбранного executable блокируется защитным launcher; полная Windows-проверка ещё нужна |

Скачиваемый `.ps1` запускает установленный официальный executable с `-i <local>`
и `-p=`. Другие пользовательские аргументы и старые config-файлы не подключаются.
Код Data Client не изменён. Исполняемый файл вручную выбирает пользователь;
записанный SHA-256 позволяет указать проверенный бинарник, но сам по себе
**не доказывает** его соответствия исследованной ревизии исходников.

## Защита запуска Windows — реализована, но не проверена на реальном Windows

* Именованный mutex блокирует два экземпляра нашего launcher.
* До запуска проверяются известные процессы Data Client, выбранный путь,
  задания планировщика и записи автозапуска. При обнаружении обычного клиента
  или его автозапуска запуск останавливается. Задания пользователя автоматически
  не отключаются и чужие процессы не завершаются.
* В Windows Firewall создаётся правило **только для выбранного executable**:
  блокировка внешних IPv4/IPv6-адресов, все протоколы, все профили. Loopback
  остаётся для локального ingest. Проверяются активное правило и его фильтры.
* Профили Firewall должны быть включены; без защитного правила клиент не
  запускается. Общесистемная политика исполнения PowerShell не понижается.
* Цикл наблюдает другие известные копии, правило, TCP-соединения выбранного PID
  и активную сессию приёмника. Внешнее established-соединение вызывает остановку.
* Собственный процесс клиента завершается перед удалением правила. Если его
  завершение подтвердить не удалось, правило **остаётся**; это записывается
  в журнал. После аварии/выключения компьютера правило также может остаться.

**Ограничения:** мониторинг периодический, не атомарный; он не гарантирует,
что другая переименованная/запущенная из другого пути копия не успела отправить
данные до обнаружения. Правило относится к выбранному executable, не ко всем
возможным дочерним программам/прокси. TCP polling не является полным аудитом
UDP, DNS или пакетов, не заменяет проверку WFP/пакетной трассировкой в Windows.
Пока это не проверено, режим нельзя называть доказанно приватным.

## Форматы и хранение

`marketorders.ingest`: объект `Orders`, поля настоящей `lib.MarketOrder`.
`UnitPriceSilver` делится на 10000. Сохраняются side, amount, expiry и время
получения. Лучшие цены — только внутри наблюдавшейся части рынка; не полная
книга. Для quote source хранится отдельно, expired/заменённый ордер не fresh.

`markethistories.ingest`: `AlbionId`, `LocationId`, `QualityLevel`, `Timescale`,
`MarketHistories[{ItemAmount,SilverAmount,Timestamp}]`. .NET ticks и масштаб
серебра обрабатываются явно. **Все Timescale 0/1/2 сохраняются в native_history**.
Для 0 нормализуются только точные часовые границы. Остальные масштабы не
превращаются в фиктивные почасовые продажи. Незнакомый numeric ID сохраняется
до синхронизации каталога, затем сопоставляется. Неизвестные персональные поля
и темы не сохраняются.
Если в истории пришло качество 0, оно сохраняется в native_history отдельно
и не превращается в качество 1 или продажи конкретного качества.

SQLite v2: source входит в ключи history и orders. Публичная и собственная
история одного часа больше не перезаписывают друг друга. Перед миграцией
создаётся `data/before-private-scanner-v2.sqlite3`; повторное открытие безопасно.
Старые `data-client` записи остаются legacy, а не объявляются задним числом
приватными. Повтор идентичного пакета в течение 5 минут не дублирует записи.

В таблице фильтр «Только мои · Private» отделён от «Публичные AODP» и legacy.
В режиме «Все источники» выбираются свежие наблюдения; один исторический час
не суммируется повторно из нескольких источников. Source/observed_at/received_at
доступны в котировке и экспорте. `own_*` счётчики — записи в базе; records в
сессии включает обновления, а не число уникальных предметов.

## Публичное чтение REST/NATS

REST остаётся независимым read-only потребителем публичных цен. Приватные
наблюдения не используются в его запросах/теле: запрашиваются только ID,
места и качества, выбранные пользователем. NATS включается отдельной кнопкой,
не автоматически. Подписчик NATS Core отправляет только CONNECT (общедоступная
учётная запись из документации AODP), SUB и PONG. Метода публикации нет.

Темы: `marketorders.deduped`, `markethistories.deduped`; данные уже нормализованы
сервером AODP, повторного деления на 10000 нет. Источник — `aodp-nats`, не private.
Это простой read-only Core-протокол, не JetStream; при требовании TLS-upgrade
останавливается, не отключает проверку TLS. Стандартный документированный
публичный NATS AODP использует `nats://` и не является каналом для наших личных
данных. Некорректные сообщения отклоняются; ошибки связи/переподключение видимы.

В текущей облачной среде прямой TCP запрещён политикой: NATS не пытается
обойти sidecar. Живое соединение Asia NATS не проверено. Подписка проверена
на записывающем **настоящем TCP loopback-брокере**; REST Asia также остаётся
заблокирован текущей политикой. На домашнем Windows эта политика облака не
действует, но успешное соединение с публичным NATS всё равно нужно проверить.

## Свидетельства сетевой проверки

См. [report.json](evidence/private-scanner/report.json),
[wire-test.log](evidence/private-scanner/wire-test.log),
[connect.trace](evidence/private-scanner/connect.trace).

Проведён эксперимент с **неизменёнными** upstream `dispatcher.go` и
`uploader_http.go` под `strace -f -e trace=connect`. Синтетические market orders
и history дошли до настоящего HTTP-приёмника приложения и временной SQLite;
проверены нормализация, дедупликация и source. Сетевые соединения — только
loopback. В положительном контроле с двумя destination оба записывающих
локальных сервера получили сообщение; при единственном local target второй
приёмник ничего не получил. `-d` остановил локальную отправку, пустой `-p`
не передал персонализированное сообщение.

Это **частичный** технический эксперимент. Поддерживающие типы, логирование,
dashboard и отключённые WS/PoW/NATS-ветви изолированы stubs; полный клиент,
updater, Npcap, игра и Windows Firewall в нём не исполнялись. Утверждать на
этом основании отсутствие всех отправок полного Windows-клиента нельзя.

Воспроизведение для разработчика: `scripts/audit_official_dispatcher.py` с
аргументами `--checkout`, `--go`, `--output`. Toolchain Go установлен из
официального дистрибутива с проверкой SHA-256; код чужого клиента в продукт
не включён, лицензия MIT переносится во временный эксперимент вместе с файлами.

## Что осталось проверить до объявления готовности

1. Актуальные официальные ToS/правила Sandbox Interactive и применимость
   к приватному режиму. Запросы `albiononline.com/terms_and_conditions` и
   `forum.albiononline.com` из среды исследования получили 403; разрешение
   не подтверждено. Использованные источники AODP не заменяют разрешение SBI.
2. На Windows запустить официальный клиент известной версии/хэша, проверить
   действие правила Firewall и успешную доставку на фактический локальный порт.
3. Во время ручного просмотра рынка проверить базу и экономическую таблицу.
4. Выполнить относящуюся к клиенту сетевую проверку (включая UDP/DNS и дочерние
   процессы), а также положительный контроль обнаружения отправки на внешний
   тестовый адрес **без реальных игровых данных**. Одна отсутствующая строка
   в TCP polling не доказательство отсутствия пакетов.
5. Проверить гонки второго клиента, автозапуск, остановку/аварию launcher,
   сохранность правил после сбоя и восстановление обычного режима вручную.

Локальные Windows-журналы launcher: `%LOCALAPPDATA%\AlbionTradeDesk\PrivateScanner\<сессия>`.
Там находятся `network-audit.jsonl` и штатный лог клиента. Они не отправляются
в облако. В журнале сети только метаданные процесса/адреса/состояния; сам
игровой трафик других программ не собирается. Отсутствие внешних TCP строк
в этом файле **не меняет** experimental/network_verified=false в интерфейсе.
Штатный лог официального клиента может содержать локальный адрес с токеном
сессии: upstream uploader пишет destination в журнал. Не публикуйте его во
время активной сессии; после остановки приёмника этот адрес аннулируется.


### Обновление названий интерфейса

В светлой версии пользовательский раздел называется **«Мои наблюдения»**.
«Источники данных» и расширенные настройки находятся в сворачиваемом меню
«Настройка приложения». Полный Private Market Scanner остаётся тем же
экспериментальным режимом; смена темы и подсказок не добавляет подтверждений
правил SBI или завершённой проверки Windows/сети. Рутинные HTTP-журналы скрыты
из консоли, но время последнего пакета и счётчики приёмника видимы в панели.
