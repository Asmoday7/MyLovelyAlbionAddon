# Приватный AOD: реализация и граница проверки

Обновлено 1 ноября 2026 года. Управляемый запуск реализован; полная проверка на Windows 10/11 с Npcap и Albion ещё не выполнена. Автовключения, автоматического восстановления сессии и заявления о подтверждённой безопасности аккаунта нет.

## Для пользователя

Откройте Trade Desk → выберите сервер → «Мои наблюдения» → ручное включение → «Запустить сборщик». Windows запросит разрешение для защитного помощника. При первом запуске выберите **установленный AOD 0.1.61 x64**, не installer. Путь запоминается. Затем вручную откройте рынок в Albion. Остановка выполняется той же панелью. Скачивать и вручную запускать скрипт не нужно.

Если Npcap отсутствует, помощник сообщает об этом и не запускает AOD. Установка — вручную с https://npcap.com/#download. Trade Desk не устанавливает драйверы или AOD автоматически. Обычный AOD, его автозапуск или другой управляемый экземпляр блокируют новый запуск; чужие процессы не завершаются.

База: **%LOCALAPPDATA%\AlbionTradeDesk\trade-desk.sqlite3**. Путь и размер доступны в панели. Из исходников запуск — start.cmd, нужен Python 3.12+. Для frozen exe Python не требуется, но этот exe должен быть собран на Windows. Новая версия программы не удаляет пользовательскую базу. Старый data/trade-desk.sqlite3 из папки запуска переносится однократно через SQLite backup, если пользовательской базы ещё нет. Явный --data-dir сохраняется для тестов/переноса.

Публичные загрузки (включая каталог) по умолчанию выключены; включаются независимо в «Источниках». Каталог не нужен для приёма: незнакомый предмет сохраняется под игровым ID и виден в аналитике. Для локализованных имён/рецептов нужен каталог. Свои наблюдения в публичные запросы не включаются. NATS включается только отдельно, через read-only подписчик.

## Что запускается

- Веб-приложение сначала эксклюзивно занимает loopback-порт. Порт не обязан быть 8765, конфликт с Anki учитывается.
- Ручная сессия получает случайный токен и фиксированный сервер. /api/private/launch включает receiver и запускает собственный PowerShell supervisor через UAC. Параметры берутся из локального JSON; пользовательский текст не вставляется в shell-команду.
- В Windows читается установленный exe и сравнивается SHA-256 с windows/aod-release.json. Ожидаемый хэш exe: **4feb2e2dd3c5e2e65f494581e3e5076b394a41bf777c936bc1bdfcc26fd1229c**. Получен из официального update-windows-amd64.exe.gz, сначала сверенного с опубликованным GitHub digest **c5ed4c046be7d7dc5c4f07bfd88ed05a10199a24ae63fbeb554aea512aac3f02**. Бинарник при вычислении хэша не запускался и в дистрибутив Trade Desk не включён. Несовпадение не игнорируется.
- Только после проверки драйвера, отсутствия других копий, включённых профилей Firewall и защитного правила запускается AOD. Config создаётся в изолированной рабочей папке.
- Наш процесс приложения защищён process-lifetime lock на папку базы. Supervisor использует отдельный глобальный Windows mutex. Отказ/таймаут остановки не разрешает повторный запуск.
- Stop создаёт локальный сигнал остановки, помощник завершает только созданный им process handle/PID и затем снимает своё правило. Если завершение не подтверждено, правило остаётся. При исчезновении HTTP receiver помощник также останавливает свой AOD. Вторые экземпляры, изменение правила или внешнее TCP Established вызывают остановку.
- Код скрипта исполняется как код приложения через PowerShell; общесистемная ExecutionPolicy не изменяется, флаг Bypass не используется. AppLocker/Constrained Language и корпоративные ограничения не обходятся.

## Настройки оригинального AOD

Проверена ревизия **c6edd9456bec4657755c25f173e8ebc7a31a17f7**, совпадающая с tag 0.1.61.

| Канал | Настройка и смысл |
|---|---|
| -i | Единственный http://127.0.0.1:<actual-port>/private/<server>/<session-token>. Заменяет стандартный AODP endpoint; список из нескольких адресов не используется. |
| -p | Явно пустой -p=. Локальный -p с обычным -i оставил бы публичную копию, поэтому эта схема не применяется. |
| -d | Не используется: отключает и локальный HTTP upload. |
| WebSocket | EnableWebsockets=false, AllowedWebsocketHosts=[] в собственном config.json/CWD. |
| NATS uploader | Не выбирается. Отдельный read-only подписчик приложения не является этим uploader. |
| Updater | В release AOD остаётся активным. Внешние адреса выбранного exe блокируются Firewall до старта, а хэш проверяется при каждом запуске. Защита updater/дочерних процессов на настоящем Windows ещё не подтверждена динамически. |

В dispatcher не найден fallback с ошибочного localhost на публичный ingest. Обычный HTTP — native JSON на /marketorders.ingest и /markethistories.ingest. HTTP 200 отправляется после успешной обработки/фиксации поддерживаемого сообщения. Надёжную очередь повторной доставки сам AOD не предоставляет. Личные поля, другие темы, неверный токен и другой сервер в URL отвергаются. Публичный API и синхронизация каталога из receiver не вызываются.

## Данные и SQLite

SQLite v3 сохраняет source в ключах orders/history. Для ордера сохраняются server, raw и normalized location, market type, item, quality, enchantment, side, price, amount, expiry, first_seen_at, observed_at и received_at. Здесь observed_at — **локальное время поступления HTTP-запроса**, а не точное время перехвата/создания ордера на сервере: такого поля нет в native AOD JSON.

Ключ текущего состояния — (server,id,source). UPSERT защищён сравнением observed_at, идентичность item/location/quality/side не меняется незаметно. Потоковая запись использует транзакции, BEGIN IMMEDIATE, busy timeout и индекс рынка. Поздно обработанный запрос с более ранним временем поступления не заменяет новое состояние. Старый сетевой replay, доставленный как новый HTTP-запрос без исходного времени, распознать достоверно нельзя.

Повтор идентичного сообщения обновляет last-seen и количество обработанных ордеров, но не количество уникальных ордеров/Amount. Частичный просмотр не удаляет отсутствующие заявки и не доказывает продажу. AOD не сообщает надёжный признак полного snapshot, поэтому удаления по отсутствию нет. Записи с явным истечением срока удаляются после семидневного запаса; Black Market с неопределённым сроком не объявляется автоматически исполненным.

Для private orders не накапливается market_snapshots на каждый просмотр; сохраняется последняя проекция quotes. Журнал events ограничен последними 2000 записями. Native history сохраняет Timescale 0/1/2 с UPSERT по bucket; неизвестный numeric ID остаётся до сопоставления каталогом. Качество 0 хранится отдельно и не превращается в конкретное качество. Неподтверждённые границы агрегатов не превращаются в выдуманные часы.

Нормализация сохраняет raw location. 0007 → 7; порталы нормализуются в соответствующий город; 3013-Auction2 → 3005/Caerleon по текущему серверному коду AODP, не в Black Market. 3003 — Black Market. Неизвестные локации сохраняются без фильтра. Живая проверка всех raw ID ещё нужна.

Quotes используются существующими аналитикой, сравнением городов и крафтом. Black Market учитывается как рынок buy orders. Основной экспорт MarketPrices сохранён; отдельная кнопка «Мои ордера · Excel» выгружает все поля последних private orders выбранного сервера.

## Закрытие файлов и HTTP

Store.connect всегда закрывает соединение в finally. В backup используется closing(sqlite3.connect(...)): стандартный with sqlite3.connect сам по себе не закрывает handle. HTTP threads не daemon, server_close дожидается их завершения; соединения имеют timeout. При закрытии останавливаются supervisor, NATS и executor. Ошибки очистки тестов не подавляются.

Исходники AlbionLocalProbe в проекте отсутствуют. Эквивалентная проверка реализована в tests/test_aod_integration.py: настоящий HTTP, конкурентные POST, backup, shutdown/join/server_close, повторное открытие и удаление реальных main/WAL файлов до удаления временной директории. Windows запустит тот же тест в CI; в текущей Linux-сессии это не подтверждение отсутствия WinError 32 на Windows.

## Что проверено

- Полный unittest suite, включая native HTTP/SQLite, невалидные batch и rollback, дедупликацию, защиту от запоздавшей обработки, регионы, raw location, запуск/остановку supervisor с **подставленным Popen**, timeout и lock приложения.
- Chromium: форма запуска, отказ от неподдержанного запуска, synthetic native orders/rescan, счётчики, журнал, Excel download, остановка receiver и мобильная ширина. Игровых наблюдений в тестовой БД нет.
- Повторный scoped experiment scripts/audit_official_dispatcher.py: неизменённые upstream dispatcher.go/uploader_http.go, настоящие локальные HTTP sinks, синтетические сообщения, strace connect и SQLite bridge. -d/empty -p/sole-local и положительный контроль нескольких адресов проверены.
- Python wheel собирается с ресурсами и без пользовательской базы. Windows build workflow и PyInstaller spec добавлены; в этой Linux-сессии Windows exe впоследствии собран; успешный результат и точные границы приведены в WINDOWS_BUILD_RESULT.md.

## Что НЕ доказано

Нет полного запуска официального Windows exe с Npcap, игры, UAC/NetSecurity/Firewall, WebView2/дочерних процессов. TCP polling не видит все UDP/DNS/короткие соединения и не заменяет WFP/полную трассировку. Правило относится к выбранному exe, а не ко всем возможным переименованным копиям и прокси. network_verified остаётся false. Тест только dispatcher не является аудитом всего клиента.

Native HTTP **не содержит serverID**. Отображается выбранный контекст сессии и «Сервер игры: не определён», а не ложная метка автоопределения. Приём от URL другого региона запрещён, но переключение сервера непосредственно в игре без остановки сессии невозможно определить по этому JSON. Перед использованием убедитесь в регионе в самом AOD. Не переключайте регион до остановки.

Шифрованные ордера клиент не расшифровывает, обходов нет. Актуальное разрешение SBI для конкретного private use case не получено. Эти ограничения явно показаны пользователю и не заменяются зелёным статусом полученного пакета.


## Доработка Windows-проверки

Политика вынесена в PrivateNetwork.ps1 и включается в управляемый и скачиваемый launcher. Полная проверка профилей/портов/протоколов/адресов повторяется во время работы. При смене процесса updater защита не снимается, пока другой процесс того же exe остаётся жив; чужой процесс не завершается.

Стандартная установка AOD обнаруживается по проверенному NSIS registry key/default path, но принимается только при совпадении SHA-256. Если установщик создал обычную scheduled task, помощник предлагает **отдельный Yes/No диалог** для временной паузы. При No ничего не меняется. При Yes приостанавливаются только задачи, прямо запускающие выбранный exe, и восстанавливаются после подтверждённой остановки. Неизвестные/кастомные записи автозапуска не изменяются. При аварии задача может остаться выключенной; имена сохраняются в локальном audit log.

В CI добавлены проверка упакованного exe с HTTP/SQLite/export/завершением процесса и тест реального NetSecurity/WFP на отдельной программе, собранной из тестового C# исходника. Проверяется loopback и блокировка TCP/UDP на документационный внешний IP; из Security log выбираются только события этой synthetic программы. Политика аудита и профили брандмауэра изолированного runner восстанавливаются. Игра/AOD/Npcap в этом тесте не запускаются. Наличие этих тестов ещё не означает, что они выполнены: фактический результат определяется отчётом Windows CI.


## Подтверждение Windows CI

См. [Windows-сборка](WINDOWS_BUILD_RESULT.md): 83 теста прошли без пропусков; упакованный exe, SQLite cleanup и реальный WFP-тест общей политики на synthetic probe успешны. Это закрывает отсутствие Windows-сборки и проверки компонентов на Windows runner. Непроверенными остаются настоящая игра/Npcap/AOD capture, сеть пользователя и полный egress оригинального клиента; network_verified не переключается автоматически.
