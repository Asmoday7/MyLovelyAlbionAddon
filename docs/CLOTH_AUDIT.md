# Проверка пользовательского расчёта ткани

Исходник: `cloth_return_calculation_with_formulas.xlsx`, один лист, 250 формул.
Книга исследована как данные. Исходный загруженный файл не изменялся.
Проверка проведена 1 ноября 2026 по времени пользователя (Asia/Vladivostok).

## Восстановленная логика после пояснения пользователя

Возврат r=0.539 применяется последовательно к возвращённым ресурсам:
первые 100 + 53.9 + 29.0521 + 15.6590819 + 8.4402451441 + 4.5492921326699.
Это **первая партия и пять повторов**, всего 211.6007191767699. Дополнение
111.6007191767699 было округлено вниз до ручного коэффициента 111 в R2.
После четырёх повторов дополнение равно 107.0514270441.

Сумма Focus Y38:Y43 = 35079.16722512491 **верна для этой длины цепочки**:
16578 × (1 + r + r² + r³ + r⁴ + r⁵). Наличие следующих строк в листе
не означает, что автор хотел включить их в итог. Первоначальная гипотеза о
«неполном итоге» после пояснения пользователя отклонена; эту сумму не исправляем.

Основной новый режим — конечные повторы, пять по умолчанию. Дробная модель
сохраняет исходную логику; бесконечная геометрическая сумма не является основным
практическим сценарием. Теоретический предел Q/(1−r) доступен только как явно
названный вариант сравнения. Ручной коэффициент 111 тоже сохранён отдельно.

## Уточнения, а не скрытые замены

* B26 подписан T7.1, тогда как E26/I26/M26 обозначают T7.0. В новой таблице
  тир и зачарование раздельные, поэтому дублирующей подписи нет.
* Заголовок «Продажа 57,3» не соответствует использованному в примере 53.9%.
  Новая модель явно показывает введённый итоговый процент. Он не считается
  вечной константой игры и не выводится сложением бонусов станка/Focus/дня.
* Ручной Focus AB8:AB36 не связан ссылками с уровнями L40:L44. Сохранён в
  сравнительных колонках; новый расчёт Focus явно использует эти уровни.
* Дробный «возврат ткани» трактуется как эквивалент доступных операций из
  возвращённых **входных материалов**, не как автоматический возврат готового
  продукта. Нужны и волокно, и ткань предыдущего тира.
* Остаток после последнего повтора показывается отдельно, не считается уже
  проданной или произведённой продукцией.
* Налоги/станция в исходных формулах отдельно не выделены. Добавлены параметры
  с нулём по умолчанию: неизвестно, было ли это уже учтено в W.
* Старый вариант прибыли на 100 + 111 и ручной серебро/Focus остаются в книге.
  Новая прибыль связана с количеством повторов и выбранной моделью ресурсов.

## Формулы

Для каждого тира T и зачарования E, начальной партии Q:

* Волокна на операцию: 2/3/4/5/5 для T4/T5/T6/T7/T8, как в исходнике и обычных
  рецептах каталога; ткань предыдущего тира — 1. Для T4 используется T3 без чар.
* Начальные материалы = Q × (цена волокна × количество + цена нижней ткани).
* Без округления, N повторов: выпуск = Q × Σ(r^k), k=0..N.
* В режиме целых ресурсов сначала вычисляется доступное число операций:
  min(floor(остаток волокна / норма), floor(остаток нижней ткани)). Возврат
  каждого материала отдельно округляется вниз, остатки сохраняются. Неполный
  рецепт не запускается; после N повторов цикл прекращается.
* Выручка = выпуск × цена продажи × (1 − дополнительные налоги/100).
* Результат = выручка − начальные материалы − выпуск × плата станции/операцию.
  Стоимость оставшихся материалов не приписывается к уже полученной выручке.
* FCE = 30 × сумма уровней T4..T8 + 250 × уровень данного тира.
* Focus начальной партии = ROUND(10 × 1.75^(T+E−1) × Q / 2^(FCE/10000)).
  Это формула исходного Excel, не подтверждённое точное игровое округление.
  Каталог хранит округлённый базовый Focus; реальный расход может отличаться.

«Целые материалы · вниз» — явное сценарное предположение. Реальная механика
случайного/дробного возврата и фактические бонусы дня здесь не подтверждены.
Вводите итоговый процент из своего станка. Например, осторожный сценарий для
Q=100, r=53.9%, N=5 даёт 208, а дробная модель — 211.6007192.

## Проверки и сохранность

* Все 250 формул исходника независимо пересчитаны LibreOffice: Excel-ошибок
  нет, сохранённые значения совпали. Исходный лист оставлен в экспортируемой
  книге с формулами и числами; новый расчёт находится на отдельных листах.
* Новая книга: Параметры, Ткань, Возврат, Проверка, Повторы, Исходная таблица.
  Промежуточные остатки доступны на листе «Повторы», без скрытых вычислений.
* `scripts/validate_cloth_workbook.py` сравнил кэш нового XLSX с независимым
  пересчётом LibreOffice: 7780 формул в каждом из четырёх сценариев, всего
  **31120 сравнений, расхождений нет**. Проверены стандартные пять повторов,
  другие уровни/налоги/станция, целые ресурсы и нулевой возврат без повторов.
* `refining.py` — единый расчёт для HTTP и кэша XLSX. LibreOffice/openpyxl
  нужны только разработчику для независимой проверки/пересборки, не пользователю
  для запуска приложения. В приложении нет нового pip/npm runtime-пакета.
* Экспорт создаёт новый файл, существующие пользовательские книги не открывает
  на запись. Настройки вкладки сохраняются локально в SQLite `user_settings`.
