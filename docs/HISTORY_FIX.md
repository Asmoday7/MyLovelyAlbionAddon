# Исправление графика истории, 1 ноября 2026

При просмотре недельного или месячного графика в игре приложение сохраняло
пакеты Timescale=1/2 в native_history, но строило график только из нормализованной
часовой таблицы history. Поэтому наличие трёх часовых точек давало «3/168 ч»
и «3/672 ч», даже если более длинная история уже была сохранена.

Теперь для периодов длиннее 48 часов график читает сохранённые исходные точки
недельной/месячной шкалы игры. Для недели предпочитается Timescale=1,
для более длинного периода — Timescale=2; при отсутствии нужной используется
другая доступная крупная шкала. Шкалы не суммируются. Повторные наблюдения одного
timestamp из разных источников выбираются по времени получения. Сервер, рынок,
предмет, качество и фильтр источника остаются частью выбора. Точки расположены
по исходным датам, а не равномерно по числу записей.

Исходные точки не раскладываются на выдуманные часы. Вместо непроверенного
часового покрытия показываются число точек и шкала игры. Продажи обозначены
как известная часть; точный полный объём за весь период не объявляется.
Часовая аналитика остальных частей приложения сохранена.

Кнопка общей истории теперь явно загружает AODP и выбирает публичный источник
только для графика, сохраняя источник текущих цен. Для периодов длиннее 48 часов
запрашиваются оба отдельных набора AODP: time-scale=1 и time-scale=6. Длительность
шестичасовых точек сохраняется; дубликаты не добавляют продажи второй раз.
В запросе используются календарные даты, правая дата расширена до следующего
дня, а график по-прежнему ограничивается выбранным окном.

Ошибки, в том числе выключенные публичные загрузки, показаны непосредственно
в диалоге под кнопкой. Публичные загрузки остаются выключенными по умолчанию.
Получение справочника или истории не публикует собственные наблюдения.

Обновление не меняет схему SQLite: ранее сохранённые native_history доступны
сразу после замены exe и перезапуска. Не удаляйте пользовательскую базу данных.

Проверка: 88 unittest на Linux, 85 успешно, 3 Windows-only пропущены;
Chromium с изолированной базой и синтетическими native/API ответами проверил
неделю, месяц, ошибку разрешения внутри диалога, загрузку общей истории при
приватных текущих ценах, сохранение фильтра цен и мобильную ширину.
Команды: `python -m unittest discover -s tests -v` и
`NODE_PATH=/opt/codex/cua_node/lib/node_modules python scripts/check_history_ui.py`.

Ответ настоящего AODP для предмета пользователя здесь не проверен: его домен
не входит в разрешённые сетевые назначения этой среды. AODP собирает наблюдения
игроков и не гарантирует полную историю всех предметов/качеств/рынков.
Предыдущий Windows exe и отчёт docs/WINDOWS_BUILD_RESULT.md относятся к сборке
до этого исправления. Новый exe должен быть собран отдельным запуском Windows CI.
