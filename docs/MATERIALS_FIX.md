# 0.1.1: одинаковый рынок в городе и внутри аукциона

Market-only сообщения могут содержать городской cluster ID (например, 1000)
либо ID аукционного помещения (1002). До исправления заявки с 1000 сохранялись
как «other» и не попадали в выбранный Lymhurst. Если тот же ордер уже был принят
с 1002, повторный пакет с 1000 отклонялся проверкой неизменности рынка.
Проблема относилась к материалам и любым другим предметам с такими LocationId.

Нормализация теперь объединяет известные городские и аукционные коды на входе.
Она также используется для истории. Исходный код остаётся в orders.raw_location.
Bare 3003 остаётся Black Market; он не объединяется с Caerleon Market.
Явный 3003-HellDen и 3013-Auction2 разрешаются отдельно по правилам AODP.
Неизвестные рынки сохраняются без предположений.

При первом запуске 0.1.1 старые orders, quotes, history, native_history и
market_snapshots приводятся к тем же ключам. Перед изменением существующих
алиасов SQLite backup сохраняется атомарно в
`before-market-location-repair-v1.sqlite3` рядом с рабочей базой.
Сама миграция транзакционная; при совпадении ключей выбирается более позднее
наблюдение, объёмы не складываются. Цены перестраиваются из сохранённых ордеров,
сохраняя исходное время наблюдения. Миграция отмечается в user_settings и
не повторяет преобразование при следующем запуске. Отклонённые ранее пакеты
не восстанавливаются из воздуха: соответствующий предмет нужно просмотреть снова.

Открытый диалог с ценами, городами и графиком теперь обновляется при новых
пакетах локального сборщика, как и список предметов. Источник истории, её качество
и период при обновлении сохраняются. Зачарование .3 и качество 1 независимы:
брусья .3 обычного качества показываются в рамке I.

У частично просмотренного рынка старая дешёвая заявка может оставаться лучшей
из известных, хотя пришли другие новые заявки. Её возраст не обнуляется.
В такой ситуации в рамке дополнительно показывается время последнего скана.
Время получения истории показано отдельно от исторических дат продаж.
Источник AODP и приватные наблюдения остаются раздельными: загрузка общих цен
не публикует и не обновляет собственные наблюдения.

Версия 0.1.1 видна в браузере и консоли. Для обновления требуется новый exe;
исправления исходников не меняют уже скачанный исполняемый файл.

Проверено на Linux: 93 unittest, 90 успешно, 3 Windows-only пропущены;
Chromium-сценарии `scripts/check_materials_ui.py` и `scripts/check_history_ui.py`
прошли на временных базах и синтетических пакетах без игры/реального API.
Сценарий материалов проходит реальный loopback HTTP, повтор одного ордера с
1002/1000, отдельные рамки и зачарование, обновление открытого графика и цены,
сохранение wire location и видимость версии. Проверены откат миграции при ошибке,
backup и повторный запуск. Windows exe 0.1.1 требует отдельной Windows CI-сборки.
