# Архитектура первого этапа

Локальное приложение Python 3.12 + SQLite + браузер. Первая версия использует
стандартную библиотеку Python и JavaScript ES modules: установка без npm,
бинарных надстроек и облачного аккаунта, одинаковый запуск на Windows/Linux.
Это допустимое ТЗ упрощение для небольшого ядра; переход на FastAPI/React
имеет смысл при развитии сложных форм и виртуализации. Таблицы сейчас используют
серверную пагинацию, а не вставляют весь каталог в DOM.

Модули: `catalog` — импорт; `storage` — транзакции/индексы/WAL;
`ingestion` — проверка цен, истории и экспериментального ingress;
`analytics` — рыночные расчёты; `crafting` — семейства рецептов, наборы,
количества и базовый бюджет; `transport` — gzip/кэш/очередь/backoff;
`web` — loopback HTTP API и фоновые задания; `export` — CSV/XLSX;
`static` — интерфейс. Бизнес-формулы не дублируются в браузере.

SQLite отделена от исходников (`data/`, ignored); для каждой HTTP-операции своя
connection, bounded serialized background worker для сетевых обновлений.
Сохранённые фильтры и избранное переживают перезапуск. SQLite backup API создаёт
согласованную копию, включая WAL; не копируем открытый .sqlite обычным shutil.

В первой схеме локализации и категории хранятся в items, ингредиенты в JSON
recipes. Это явное упрощение MVP относительно целевой нормализованной схемы ТЗ.
Схема имеет `user_version=2`: миграция источников history/orders сохраняет
резервную копию v1. Аддитивная таблица `craft_packs` хранит определения наборов,
не копии котировок. Все новые цены сразу доступны повторному расчёту. Перед
дальнейшим развитием потребуются таблицы профилей, портфеля и пользовательских операций. Полные
рыночные сделки не выводятся из публичных min/max котировок.

Сервер слушает только 127.0.0.1. Host и Origin проверяются; нет внешних шрифтов,
скриптов, аналитики, телеметрии и автоматического управления игрой. Данные из
источников вставляются в DOM через textContent. Скачиваемые CSV защищают текстовые
ячейки от formula injection; числовые значения остаются числами.

`static/crafting.js` управляет выбором предмета, буфером обмена и отображением;
формулы находятся в Python. `/api/craft/search`, `/api/craft/plan`,
`/api/craft/packs`, `/api/craft/pack`, `/api/craft/delete` обслуживают наборы.
`/api/craft/refresh` ставит REST-запросы в общую очередь: группирует ингредиенты
по городу/качеству, добавляет результат, дедуплицирует и разбивает по 100 ID.
Наборы ничего не отправляют в игровой клиент и не включают приёмник автоматически.
