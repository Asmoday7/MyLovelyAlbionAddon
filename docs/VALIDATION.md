# Проверка текущего этапа — 31 октября 2026

## Выполнено

* Linux, Python 3.12.14, SQLite: приложение запущено; функциональные HTTP-запросы
  к реальному каталогу работают. Процесс сервера — отдельный от сохраняемой базы.
* `python3 -m albion_trade_desk sync-catalog` выполнен дважды: 12 237 предметов,
  12 917 вариантов рецептов. Повтор не дублирует каталог; используется HTTP-кэш.
* `python3 -m unittest discover -s tests -v`: **26 тестов прошли**.
  Есть проверки арифметики VWAP/coverage, закрытых интервалов и границ,
  недопустимых значений, year-0001/zero-price, zero-sales, старых наблюдений,
  разделения регионов/качеств/городов, BM buy-only, дедупликации и rollback.
* HTTP integration: импорт fixture-ответа, фильтры, избранное, перезапуск
  connection, CSV, согласованная SQLite backup, Host/Origin и ошибки запроса.
  Синтетические рыночные fixtures существуют только во временных тестовых базах.
* Транспорт: gzip, TLS context, persistent cache, batching <4096 символов,
  429 epoch reset/backoff; 403 не ретраится как успешный пустой ответ.
* `node --check albion_trade_desk/static/app.js`: прошёл.
* Реальный Chromium/Playwright: каталог → поиск T4_BAG → карточка восьми рынков
  → выбор строк → скачивание XLSX → вкладка источников; проверена мобильная
  ширина 390 px без переполнения body, ошибок JS нет.
* Скачанный браузером XLSX независимо открыт через **openpyxl**: 10 реальных
  предметов, 33 колонки, ID/локализации сохранены; отсутствующие рыночные цены
  остались пустыми. Openpyxl используется только для независимой валидации,
  не является runtime-зависимостью приложения.
* Эксперимент ingress подтверждает сопоставление предмета/региона/качества,
  деление денег на 10000, обработку .NET ticks и повторного пакета. Это не
  тест с настоящей запущенной игрой.

Изначально HTTP-тесты были отклонены песочницей (запрещены sockets); повтор
в подходящем execution-контексте прошёл, тесты не отключались. Два первых
браузерных smoke-скрипта ожидали ошибочное тестовое название «Сумка знатока»
вместо реального «Сумка (знаток)»; сохранённый smoke выбирает точный ID и проходит.

## Не подтверждено / не выполнено

* `python3 -m albion_trade_desk probe --server east`: exit 1,
  `Tunnel connection failed: 403 Forbidden`. Это отказ сетевой политики прокси,
  не ответ API Asia. В runtime custom allowlist по-прежнему пуст; изменения
  доменов пока только в draft. Живые prices/history/BM и временные границы
  **не подтверждены**, acceptance Phase 1 открыт.
* Сайты конкурентов за пределами GitHub заблокированы той же политикой;
  аудит их возможностей явно отделён от заявлений в ТЗ.
* Windows и Microsoft Excel UI не запускались. `start.cmd` подготовлен,
  Windows/Linux CI настроен, но удалённый workflow ещё не исполнялся.
* NATS и массовые Asia SQL-дампы: документация найдена, технические подключения
  не выполнены. Orderbook endpoint не обнаружен, глубина остаётся неизвестной.
* Crafting profit, BM opportunities, enchanting, оптимизатор и портфель —
  последующие этапы, не выдаются за готовые функции.

Для завершения живой проверки: сохранить сетевые настройки среды и
опубликовать их; затем повторить `probe`, проверить интерпретацию timestamps,
выбрать реальные предметы, получить prices/history и зафиксировать результаты.


## Дополнение: Private Scanner и конфликт с AnkiConnect

Отдельным hotfix-коммитом исправлен Windows SO_REUSEADDR: порт занимается
эксклюзивно, при конфликте выбирается следующий свободный. Тест с имитацией
AnkiConnect проверяет, что Anki остаётся доступен на старом порту, а приложение
работает на другом. Перед hotfix прошли 29 тестов в отдельном checkout только
с исправлением, без незавершённых изменений сканера.

Для текущего дополнения: 45 тестов обнаружено, 44 прошли, 1 пропущен на Linux
(разбор PowerShell через Windows Parser; запускается в Windows CI). Проверены
миграция v1→v2, изоляция собственных/публичных записей, native Timescale 0/1/2,
отложенное сопоставление numeric ID, единицы NATS deduped, отказ при личных полях,
разные регионы/токены, остановка сессии, дедупликация и read-only NATS wire.

Chromium smoke прошёл: добровольное включение, запрет запуска без подтверждения,
скачивание привязанного к сессии Windows-launcher, остановка, отсутствие ошибок
JavaScript и мобильная раскладка. Запущено на 8770; launcher использует этот
фактический порт. Полная Windows/game проверка при этом не выполнялась.

Реальные неизменённые dispatcher.go/uploader_http.go upstream исполнены в
изолированном Go wire-эксперименте под strace; рыночные fixtures дошли до
настоящего HTTP-приёмника и временной SQLite. Подробнее —
[PRIVATE_SCANNER.md](PRIVATE_SCANNER.md) и [сетевой отчёт](evidence/private-scanner/report.json).
Граница проверки указана явно: это не трассировка полного Windows-клиента
с updater/Npcap/игрой, не доказательство соответствия правилам SBI.

Live Asia REST/NATS и официальные правила SBI из текущей среды остаются
непроверенными из-за ограничений доступа. Критерий готовности Private Scanner
**не выполнен**; интерфейс не объявляет сеть verified и не включает режим
автоматически. Следующий обязательный этап — Windows/game/network acceptance,
описанный в PRIVATE_SCANNER.md.
